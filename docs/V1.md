# What stands between here and version 1

Written 2026-08-23 from an audit that read the code rather than the reports:
six auditors over the requirement list, each attacked by a second agent whose
job was to overturn it. Where a verdict was overturned, the overturned one is
the true one.

The finding that matters most is not any single defect. It is that
`game/forge/tests/drive.ts` emits three events no running code can produce
(`topic`, `stashed`, `chose`), so "300 quests driven to completion, 0 rejected"
measured the engine and not the game. On the committed sealed city, **3 of 5
quests cannot be finished by a player, and the first main quest stops at step
2.** Any number quoted from that harness has to be re-earned through the real
producers.

# game-box: stage audit

## Landed since this was written (2026-08-23)

The three breaks that made the game unfinishable all have real producers now:

- **`stashed`** — `@gb/app` `src/stashing.ts`. A stash objective names the room,
  the surface and the item; the spot exists only while the step is open and one
  of its pool is in hand, and `E` emits `{itemId, interiorId, anchorId}`.
- **`chose`** — `@gb/quest` publishes `objective.choice` (`prompt`, and
  `options: [{key, label}]`, never where a road leads), `@gb/hud` draws the
  question and the buttons on the open step only, `@gb/app` routes the click.
- **`topic`** — `@gb/talk` added an `ask_about` move. Credited when the player
  puts the NPC to that subject, never by a conversation that wanders onto it.
  The one-line version the audit imagined fails talk's own tests both ways.

Also closed: the free-text decider is a forced tool call whose parameters are
the menu; the greeting reaches the panel; the quest tab is `log.journal()` with
the hand mapper deleted, so hidden steps no longer leak (`announce` handles only
quest-started, quest-complete and quest-failed, checked by grep); `acted`,
`abandon` and the moved glass constant; and cars scale with lane metres rather
than one flat cap.

Then forge rebuilt the harness that had been lying. `drive.ts` is gone; a quest
is now played off `objectives()` alone, and what the player can do comes from
the fields a line publishes. **444 of 444 generated quests are completable by a
player**, across two themes at four city sizes, with nothing blocked. The
counterfactual, measured by mutation: 72% without the choice options published,
87 to 95% without the put-down.

And the door inversion had a cause nobody guessed. A floor of 6 fails no test;
there was no **ceiling**. About one building in eight opens now, never fewer
than the four things a town needs and never half the town. A 1x1 town went from
50 to 100% open to 33 to 40%; 3x3 and up is byte-identical to before.

Still open from the blocker list: a thing left somewhere is not drawn on the
surface (with scene), nothing marks the main line (with quest, then hud), the
premise stage, the save losing the player's position, and the sampler not being
pinned so a refresh with the model on wipes the playthrough.


## 1. Verdict

Still in development. Not issue-hunting. The engine is largely done and well tested, but the game on top of it is not finishable: on the committed sealed city, 3 of the 5 quests cannot be completed by a player, including the first main quest, which dead-ends at step 2.

## 2. What is genuinely finished

The parts below have code and a number behind them.

- City generation. Seeded, deterministic offline, 20x20 builds in 1.49 s (3,024 buildings, 1,308 people, 200 quests), `gb check` 0.343 s. 12 seeds gave 12 distinct grids. Theme changes the plot mix and prose (9 distinct mixes, game/forge/tests/theme.test.ts:21).
- Export and reopen. 6.15 MB single JSON, opens in 140 ms, reseals to the same hash, a one-character tamper is rejected. 6/6 bundle tests.
- Quest engine. Ten step kinds, branching, failWhen, abandon, reward payout. 51/51 quest tests.
- Talk. Clickable menu with no model call, free typed chat, and both paths work with the model down. 33/33 talk tests.
- HUD. Quests, map, items, controls; one window at a time; follow and give up. 43/43 hud tests.
- Playable loop, for the step kinds that work: an NPC offers a job, you take it, `collect` / `goto` / `deliver` / plain `talk` credit, the quest completes and pays. End to end at game/app/tests/contract.test.ts:1137.
- Movement and feel: crouch, jump, right-click zoom, crowd avoidance with personal space (5 measured tests), fog, wet-street reflections, near-black facades.
- Save and resume for money, inventory, stolen, flags, reputation, companions, clock.

## 3. Features with no code at all

Ordered by how much the game is missing without them.

1. **A way to put an item down.** `stash` steps advance only on `{kind:'stashed'}`; the only emitter in the repo is the test harness game/forge/tests/drive.ts:66. Forge writes these steps with weight 3 (5 on neon). Owner: **@gb/app** (a put-down target plus the event).
2. **A choice UI.** `choice` steps advance only on `{kind:'chose'}`; same story, only tests emit it. The objective carries no prompt and no options, and HudIntent has no option-picked member. Owner: **@gb/quest** (publish options) + **@gb/hud** (draw) + **@gb/app** (route).
3. **The premise.** Stage one of the pipeline he described does not exist. No premise writer, no prompt file, nothing that says why the town exists. The layout is story-blind by construction (`grep -n theme game/forge/src/layout/*.ts` returns 0). Owner: **@gb/scribe** + **@gb/forge**.
4. **Player position in the save.** PlayerStateSchema has no position field, so every resume puts you back at the spawn door. The tracked quest is lost too. Owner: **@gb/play** + **@gb/app**.
5. **Opening a city file you were sent.** Export downloads a file; the only import is `?bundle=` in the address bar. No file input anywhere. Owner: **@gb/app** boot.
6. **The cyberpunk place vocabulary.** No hospital, police station, corporate office or nightclub in the enum or anywhere downstream. Still the market-town list. Owner: **@gb/world**, then forge weights, furnish dressers, kitbash words.
7. **Minigames with a persistent score, and a quest step that credits beating one.** Zero hits repo-wide. Owner: a new box plus a `play` step kind in **@gb/quest** and a score field in **@gb/play**.
8. **Neon as light.** No PointLight, SpotLight or RectAreaLight anywhere outside a dev preview. A wall a metre from a burning sign is lit by moonlight. Owner: **@gb/kitbash** + **@gb/scene**.
9. **Screens that play something.** No VideoTexture, no HTMLVideoElement, no time node in any material. The TV is one static emissive colour. Owner: **@gb/furnish**.
10. **The bundle naming its art packs.** Every exported city carries `"requires": []`, and the world file pins nothing about which building model a plot got. Adding one building look changed 23 of 123 plots in a replay, silently, with the contentHash still matching. Owner: **@gb/world** schema + **@gb/bundle** + **@gb/prefab**.
11. **Lip sync.** No morph target or jaw bone path exists in the cast at all. Owner: **@gb/cast**.
12. **npc-lost / item-lost failure producers.** Only time-limit can fire in play. Owner: **@gb/app**.
13. **Real windows and balconies.** The pane is a 1.5 cm opaque emissive slab; balconies are explicitly filtered out of prefab. Owner: **@gb/furnish** + **@gb/prefab**.
14. **Streaming or LOD.** Culling is not loading; a 50-block city pays its whole build cost at open. Deliberately deferred, and 50 blocks is unreachable anyway (panel clamps to 24).

## 5. Version-1 blockers, as distinct from polish

1. **Two of ten step kinds are unreachable in play** (`stash`, `choice`), and both are in the live generator pool. 3 of 5 quests in the committed city are unfinishable; the first main quest stops at step 2.
2. **The journal spoils secrets.** A `hidden: true` step is listed from the moment the quest is taken. TipOff is a live default recipe.
3. **Quest givers say nothing** when the panel opens.
4. **Resume loses the player.** Position is not saved, and neither is the tracked quest.
5. **With the model on, refreshing wipes the playthrough.** Nothing pins the sampler (no temperature, no seed, three identical POSTs to the live sidecar returned three different answers), so the regenerated city gets a new contentHash, `Bundle.resume` refuses, and session.ts:32-34 clears the save. That is data loss on a refresh.
6. **Typing in the creation panel drives the game underneath.** interaction.ts:69 binds on document and checks only `hud.typing`. Typing "quiet coastal town" moves the clock twice and toggles the weather.
7. **The boot panel does not close the hud window.** Escape and Tab go to the hidden window behind it.
8. **"Most buildings stay shut" inverts on small cities.** FEWEST = 6 is applied to the batch, so 1x1 gives 6 of 9 open, and one seed gave 6 of 6. The panel allows 1x1 and the app's own tests build at that size.
9. **The green test number hides all of this.** drive.ts emits `topic`, `stashed` and `chose`, three events no running code can produce, so "300 quests driven to completion" measures the engine, not the game.
10. **@gb/prefab as the tree stands would reject its own pack** (load.ts:32 wants a screens atlas that pack/ does not have), dropping every plot to kit buildings. Mid-edit, but it must not ship that way.

Polish, not blockers: neon lights, pavement tone under non-neon themes, home vs corpo interiors, gestures, lip sync, TV content, Grok ads, balconies, 50 blocks, LOD, city growth, a provenance field, the theme-blind street plan.

## 6. Shortest credible path to version 1

**Wave A, make the loop finishable.** A2 runs in parallel with the rest; A1, A3, A4 are all in @gb/app, so one agent takes them in sequence.

1. A2a (@gb/quest): put `prompt` and `options` on a choice objective, contract change alongside the old shape.
2. A2b (@gb/hud) and A2c (@gb/app) in parallel once A2a lands: draw the options, add the `chose` intent, route it.
3. A1 (@gb/app): a put-down target that emits `stashed`, plus the key in the controls tab.
4. A3 (@gb/app): switch reporting.ts to `log.journal()` and carry `state`, `optional`, `count`, `kind` through; add `kind` to the hud entry.
5. A4 (@gb/app): render `opening.line`.
6. Then (@gb/forge tests): rewrite drive.ts to credit through the real producers. Until that lands, the 300-quest number will keep hiding this class of bug.

**Wave B, four boxes in parallel, none of them touching each other.**

- B1 @gb/play + @gb/app: position and tracked quest in the save.
- B2 @gb/app boot: focus guard on the interaction listener, close the hud window when the panel opens, add the file input for import.
- B3 @gb/forge: apply the door floor to the town, not the batch.
- B4 @gb/scribe + @gb/app: pass the progress port into the loader.

**Wave C, the real remaining features. C1 and C2 are independent.**

- C1 @gb/scribe + @gb/forge: the premise pass. Write it first, fill `InstanceRequest.premise`, give write-quest a premise hole, and let it bias the plot mix. This is the largest piece of the pipeline he described and the one with nothing behind it.
- C2 host + @gb/sidecar + @gb/bundle: pin the sampler (seed and temperature end to end) so the model path is deterministic, or make resume tolerate a regenerated city. Either closes the data-loss path.

**Wave D, polish, all parallel and none blocking v1:** home interior language, sign and lamp lights, pavement tones under non-neon themes, gesture calls from talk, the prefab screens atlas, a guide button, and deleting PlaceNamer.

Waves A and B can overlap everywhere except @gb/app, which is the bottleneck box: A1, A3, A4, B1, B2 and B4 all land there. If you want wall-clock speed, that is the queue to split by file, or the one agent to give the longest run.
